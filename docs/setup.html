todo-board · setup

Your own task board, kept current by your agents

A private task board on your Mac. Claude Code and Codex find or create a card when you ask for a change or a review, check off steps as they finish, and close what they can verify. It listens on 127.0.0.1 only, with no login, and nothing leaves your Mac.

  • Backlog
  • Today
  • In progress
  • Blocked
  • Done

Before you start

  • macOS with Docker Desktop or OrbStack installed and running.
  • git.
  • Claude Code, Codex, or both. Setup wires up whichever it finds.
  • jq and curl come with current macOS. On an older release, run brew install jq.

You don't need Go. Anything compiled for your Mac is built inside Docker. Setup takes about five minutes, mostly the image build.

Install

zsh
git clone git@github.com:kcompton15/Todo-Board.git
cd Todo-Board
scripts/team-setup

Clone it anywhere you like. The script finds its own location. Add --dry-run to preview the changes first. It's safe to rerun at any time.

When it finishes

  1. Open 127.0.0.1:7337. You should see an empty board.
  2. Start a new Claude Code session. The board rules and your active cards load at the start.
  3. Start a new Codex session and approve the hook named Loading active task board when Codex asks. You only do this once.

Would you rather have an agent do the setup? Paste docs/prompts/setup.md into Claude Code or Codex.

Setup never edits your ~/.claude/CLAUDE.md or ~/.claude/settings.json. The Claude side lives entirely in the plugin. Before it changes an existing Codex file, setup saves a backup next to it named *.bak-todo-board-<timestamp>.

The plugin also adds three commands: /todo-board:setup, /todo-board:doctor and /todo-board:reconciler.

How it behaves day to day

You don't have to do anything. Before creating a card, the agent runs todo find, so it updates an existing card rather than making a duplicate. It creates one card per outcome, with steps as subtasks, and picks one of four kinds:

workYou asked for a change. Closed only once verified; otherwise left "ready to close".
reviewYou asked for a review. MR URL in notes; closed when the findings are delivered.
followupSomething only you can do. Agents never move it.
probeAn investigation worth finding again. Closed when the answer is delivered.

If you want something tracked for certain, say "track this on my board". You can use todo yourself, too:

zsh
todo ls
todo add "Ship the quote rounding fix" --kind work --project Billing
todo help

Updating

zsh
cd Todo-Board && git pull && scripts/team-setup

The Claude plugin is read straight from your clone, so new rules and commands apply at the next session start, or after /reload-plugins. Rerunning setup rebuilds the container when server code changed and refreshes the Codex block.

Jira links optional

The board accepts Jira links only when the server knows your Jira host. Start the container with it set to a bare hostname. Without it, Jira links are rejected. GitLab merge request links on gitlab.com always work. Set it before the first start and keep it set. Changing or removing it after Jira links exist stops the server from loading the board.

zsh
TODO_JIRA_SITE=yourcompany.atlassian.net docker compose up -d

Weekday notifier optional

The notifier sends a macOS notification at 09:00 on weekdays. It covers a Monday digest of blocked cards, remind: daily, remind: weekly and remind: YYYY-MM-DD lines in card notes, probes that have sat for more than a day, and work that has been In progress for more than five days.

zsh
scripts/install-board-notifier
scripts/install-board-notifier --uninstall

Reconciler optional

The reconciler closes cards on its own once the evidence is in: the required MRs are merged, the Jira issue is Done, or (for reviews) you approved or left substantive findings on every MR in the round. It runs on weekdays at 09:20, 11:20, 13:20, 15:20, 16:45 and 18:30 Central.

It reads GitLab as you, through glab, and Jira with your API token. It never writes to either. It only changes your board, and every change shows up in the card's activity.

The easiest route is /todo-board:reconciler in Claude Code. To do it by hand:

  1. Sign in to GitLab: glab auth login --hostname gitlab.com.
  2. Create a Jira API token at id.atlassian.com and store it in your Keychain. Don't paste it at the interactive security ... -w prompt, because that prompt cuts input off at 128 characters and Atlassian tokens are longer. Use the command below instead, with your own email.
  3. Build, configure, probe, then enable. --configure detects your GitLab user and Jira email and saves them with the Jira site to ~/.config/todo-board/reconciler.json, so check what it prints. --jira-site is required the first time. --disable installs without scheduling, and --probe does one read-only dry run under launchd. The probe may stall on a Keychain prompt asking whether board-reconciler can read atlassian-api-token. Click Always Allow.
zsh
read -rs "TOKEN?Paste Jira API token: " && \
  security add-generic-password -U -a "you@yourcompany.com" -s atlassian-api-token -w "$TOKEN" && \
  unset TOKEN

make build-darwin
scripts/install-board-reconciler --configure --jira-site yourcompany.atlassian.net
scripts/install-board-reconciler --disable
scripts/install-board-reconciler --probe
scripts/install-board-reconciler --enable

To check on it, run ~/.local/bin/board-reconciler --status. To stop it, run scripts/install-board-reconciler --uninstall, which keeps its state, logs and your config file. docs/RECONCILER.md has the config fields and the full rules.

Claude Desktop optional

The regular Claude Desktop chat app can use the board through a local MCP server. Run make install-claude-desktop, then quit and reopen Claude Desktop. Claude on the web or your phone can't reach a board on your Mac.

Troubleshooting

Start with scripts/board-doctor. It checks each piece and prints the fix for anything that fails.

SymptomFix
todo: command not foundAdd ~/.local/bin to PATH: echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && exec zsh
Board unreachableStart Docker, then run docker compose up -d in the clone.
Port 7337 takenTODO_PORT=7347 scripts/team-setup, then add export TODO_URL=http://127.0.0.1:7347 to ~/.zshrc.
No board context in ClaudeCheck claude plugin list, then start a new session.
No board context in CodexStart a session and approve "Loading active task board".
Codex block "contains other sections"An old hand-made block has its BEGIN marker above unrelated text. Move the marker down to the heading of the board section and rerun.
Jira links rejectedStart the container with TODO_JIRA_SITE=yourcompany.atlassian.net.
Reconciler probe never finishesA Keychain prompt is waiting. Click Always Allow.
~/.local/bin/todo points elsewhereAn older todo is installed. Move it aside and rerun setup.

The board staying down never blocks your agents. They mention it once and carry on with the real work. The board simply misses those updates.

Uninstall

zsh
scripts/team-uninstall

This removes the plugin, the Codex block and hook, the todo link, any reconciler or notifier installed with the default labels, and stops the container. Your cards stay in data/ until you delete the clone.
